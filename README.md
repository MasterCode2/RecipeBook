# RecipeBook

Учебный REST API для хранения рецептов на ASP.NET Core Minimal API. Данные сохраняются в PostgreSQL через Entity Framework Core.

## Возможности

- Создание, получение, обновление и удаление рецептов.
- Проверка названия, ингредиентов, шагов и времени приготовления.
- Поиск по названию без учёта регистра и фильтр по максимальному времени.
- Сортировка по времени приготовления, затем по ID.
- Постраничная выдача с общим количеством подходящих рецептов.
- Асинхронное чтение и сохранение данных.
- Swagger UI для ручной проверки API.

## Технологии

- .NET 9 / ASP.NET Core Minimal API
- Entity Framework Core Design 9.0.4
- Npgsql.EntityFrameworkCore.PostgreSQL 9.0.4
- PostgreSQL 17 в Docker
- Swashbuckle.AspNetCore 10.2.3

## Локальный запуск

Потребуются .NET 9 SDK, запущенный Docker Desktop и исходники проекта. Команды ниже предназначены для PowerShell. Выполняйте команды dotnet в папке с файлом проекта .csproj.

### 1. Подготовить PostgreSQL

Если контейнер recipebook-postgres уже создан с нужными настройками, достаточно запустить его:

```powershell
docker start recipebook-postgres
```

Для первого запуска на новом компьютере создайте хранилище и контейнер. Замените YOUR_LOCAL_PASSWORD своим локальным паролем; используйте тот же пароль в строке подключения на следующем шаге.

```powershell
docker volume create recipebook-pg17-data
docker run --name recipebook-postgres -e POSTGRES_DB=recipebook -e POSTGRES_USER=recipebook -e POSTGRES_PASSWORD=YOUR_LOCAL_PASSWORD -p 127.0.0.1:5433:5432 -v recipebook-pg17-data:/var/lib/postgresql/data -d postgres:17
```

Приложение подключается к 127.0.0.1:5433; PostgreSQL внутри контейнера слушает порт 5432. Данные находятся в volume recipebook-pg17-data и сохраняются при перезапуске контейнера. Не удаляйте volume, если данные нужны.

Переменные POSTGRES_DB, POSTGRES_USER и POSTGRES_PASSWORD инициализируют базу только при первом запуске с пустым хранилищем. Они не меняют пароль существующей базы.

Проверить готовность базы:

```powershell
docker logs recipebook-postgres
```

Дождитесь сообщения о готовности принимать подключения.

### 2. Настроить подключение

В проекте уже задан UserSecretsId. Сохраните строку подключения локально:

```powershell
dotnet user-secrets set "ConnectionStrings:RecipeBook" "Host=127.0.0.1;Port=5433;Database=recipebook;Username=recipebook;Password=YOUR_LOCAL_PASSWORD"
```

Не добавляйте настоящий пароль в README или файлы, отправляемые в Git. User Secrets предназначены для локальной разработки и не являются зашифрованным хранилищем.

### 3. Установить зависимости и применить миграции

```powershell
dotnet restore
```

Если инструмент dotnet-ef ещё не установлен:

```powershell
dotnet tool install --global dotnet-ef --version 9.0.4
```

Если он уже установлен, проверьте версию командой `dotnet ef --version`; для этого проекта используйте совместимую версию 9.x.

Примените существующие миграции, чтобы создать таблицы:

```powershell
dotnet ef database update
```

Создавать новую миграцию для обычного запуска проекта не требуется.

### 4. Запустить API

```powershell
dotnet run --urls http://localhost:5000
```

Откройте Swagger UI: http://localhost:5000/swagger

## Методы API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /recipes | Список с фильтрами и пагинацией |
| GET | /recipes/{id} | Рецепт по ID; 404, если не найден |
| POST | /recipes | Создание; 201 и заголовок Location |
| PUT | /recipes/{id} | Обновление; 200 или 404 |
| DELETE | /recipes/{id} | Удаление; 204 или 404 |

### Фильтры и страницы

| Параметр | Правило |
|---|---|
| title | Необязательный поиск по названию; строка из пробелов отклоняется |
| maxCookingTime | Необязательное максимальное время, от 1 до 1440 минут |
| page | Номер страницы от 1 до 10000; по умолчанию 1 |
| pageSize | Размер страницы от 1 до 100; по умолчанию 10 |

Пример совместного поиска:

```http
GET /recipes?title=кур&maxCookingTime=30&page=1&pageSize=5
```

Оба фильтра применяются одновременно. Результат сортируется по CookingTimeMinutes, затем по Id. Поиск использует PostgreSQL ILIKE: символы % и _ в поисковом тексте имеют значение символов шаблона.

Ответ списка содержит items, totalCount, page и pageSize. totalCount — количество совпадений после фильтров, но до пагинации. Если совпадений нет или страница пуста, API возвращает 200 и пустой items.

### Создание и обновление

Пример тела POST и PUT:

```json
{
  "title": "Омлет",
  "ingredients": ["2 яйца", "50 мл молока"],
  "steps": ["Смешать яйца и молоко", "Приготовить на сковороде"],
  "notes": "Подавать горячим",
  "cookingTimeMinutes": 10
}
```

Название обязательно. Ингредиенты и шаги должны содержать хотя бы один элемент; пустые строки и строки из пробелов не допускаются. Время — от 1 до 1440 минут включительно. Notes необязателен. Ошибки этих проверок возвращают 400.

ID нового рецепта назначает база. В PUT ID передаётся в адресе, а в JSON указываются все обновляемые поля.

## Ручная проверка в Swagger

1. Создать рецепт: ожидать 201, получить ID и Location.
2. Получить его через GET: ожидать 200 и сохранённые данные.
3. Обновить через PUT и проверить изменения через GET.
4. Отправить PUT со временем 0: ожидать 400; сохранённые данные не должны измениться.
5. Проверить фильтры совместно и переход между страницами.
6. Удалить рецепт: ожидать 204; последующий GET должен вернуть 404.

## Границы текущей версии

Проект представляет собой учебный API для локального запуска. Пользовательский сайт, авторизация и автоматические тесты пока не реализованы. Swagger служит интерфейсом для ручных запросов.
